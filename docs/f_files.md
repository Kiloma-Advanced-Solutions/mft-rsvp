## `lib/` — the non-visual half of the app

| File | Kind | What it does |
| --- | --- | --- |
| `lib/types.ts` | [both] | **The domain model — read this first.** `UserRole`, `User`, `EventAccess`, `EventStatus`, `EventCategory`, `AccentKey`, `EventLocation`, `EventRecord`, `RegistrationStatus`, `Registration`, `EventWithContext`. Heavily commented; the comments are the spec in miniature |
| `lib/db.ts` | [S] | **The repository.** `db.users` / `db.events` / `db.registrations`, each async `list / get / create / update / remove`, plus `db.reset()`. Deep-copies on read, stores state on `globalThis` to survive hot reload, cascades registration deletes when an event is removed. Also exports `EventInput`, `EventPatch`, `RegistrationInput`, `RegistrationPatch` |
| `lib/seed.ts` | [S] | `SEED_USERS` (5 people), `DEFAULT_USER_ID` (`u-maya`), `createSeedEvents()` (12 events), `createSeedRegistrations()`. Timestamps are relative to "now" the first time the store is built, so the past/present/future spread is always sensible |
| `lib/session.ts` | [S] | `SESSION_COOKIE` (`eb_persona`), `getCurrentUser()` — never null, falls back to the default persona — and `setCurrentUser()`, which can only be called from a Route Handler |
| `lib/permissions.ts` | [both] | **The one place the rules live.** `isHost`, `isInvited`, `canViewEvent`, `canManageEvent`. Pure functions over already-loaded records: no I/O, no framework import |
| `lib/events.ts` | [S] | The service layer. `getBoard(viewer, filters)` → `{ upcoming, past, visibleCount, accessCounts }`. Private helpers: `toBoardEvent` (derives hosts, `goingCount`, `pendingCount`, the viewer's registration, `viewerCanManage`, attendees), `splitByTime`, `countByAccess`. Exports the `BoardEvent` and `Board` types |
| `lib/board-filters.ts` | [both] | The board's URL contract. `CATEGORY_PARAM`, `ACCESS_PARAM`, `ACCESS_ORDER`, `BoardFilters`, `parseBoardFilters()` (drops unknown values instead of 404ing), `boardHref()`, `hasActiveFilters()`. Deliberately free of any `db` import so the client filter bar can use it too |
| `lib/api.ts` | [both] | `ApiError` (with `badRequest` / `forbidden` / `notFound` / `conflict` factories), `jsonOk`, `jsonError`, `withErrorHandling`, `readJson` — all server side — and `fetchJson`, the client counterpart that unwraps success and throws the server's message |
| `lib/labels.ts` | [both] | Every user-facing string: `ACCESS_LABELS` / `_DESCRIPTIONS` / `_TONES`, `EVENT_STATUS_LABELS` / `_TONES`, `REGISTRATION_LABELS` / `_TONES`, `CATEGORY_LABELS` / `CATEGORY_ORDER`, `BOARD_LABELS`, `LOCATION_KIND_LABELS`, `locationLabel()` |
| `lib/date.ts` | [both] | Formatting pinned to `en-GB` to prevent hydration mismatches. `formatDayNumber`, `formatMonthShort`, `formatWeekdayShort`, `formatDateLong`, `formatDateWithYear`, `formatTime`, `formatTimeRange`, `formatDuration`, `isPast`, `daysUntil`, `formatRelativeDay`, `toDayKey` (calendar grouping, local time not UTC), `toDateTimeLocalValue` / `fromDateTimeLocalValue` |
| `lib/cx.ts` | [both] | `cx(...)` — join class names, drop falsy. Replaces a `classnames` dependency |

**Missing, and named in `dec_decisions.md` as an open question:** a
`lib/registration.ts` for "is registration open", "what status does registering
produce", "is this event full".

| `Modal.tsx` | [C] | `Modal` (native `<dialog>`, so focus trapping / top layer / Escape come from the platform) and `ConfirmDialog`. Controlled: `open` drives it, `onClose` fires for every way out |

| `SegmentedControl.tsx` | [C] | `SegmentedControl<T>` and `SegmentOption<T>` — single-choice switch with optional counts. What the stretch-goal list/calendar toggle should use |
| `Spinner.tsx` | [S] | `Spinner` and `LoadingBlock` |
| `Toast.tsx` | [C] | `ToastProvider` (mounted once in the root layout) and the `useToast()` hook |
