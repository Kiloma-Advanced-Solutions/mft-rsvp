# Memory bank

The project's long-term memory. Read this folder before starting a session, and
update it at the end of one. Everything here is Markdown and lives in git, so
the history of the memory bank is reviewable like any other code.

| File | What it holds | When to update |
| --- | --- | --- |
| [`a_architecture.md`](a_architecture.md) | Client / server / repository split, the layers, what each layer contains, the stack | When a layer is added, removed or given a new responsibility |
| [`c_conventions.md`](c_conventions.md) | How we work: branch per feature, commit per small task, which folder each kind of file goes in | When a working rule changes |
| [`d_terminology.md`](d_terminology.md) | The words of the domain — host, access mode, going, pending | When the product gains a new concept |
| [`dec_decisions.md`](dec_decisions.md) | Every decision made so far, with the reason | Immediately after a decision, before it is forgotten |
| [`s_sessions.md`](s_sessions.md) | Session log: goal, plan, task list, what is done, what is open, PRs | During and at the end of every session |
| [`r_references.md`](r_references.md) | Links and sources used to write code or solve bugs | Whenever a link actually helped |
| [`u_user-setup.md`](u_user-setup.md) | The machine, the tooling and the Claude Code settings this project is developed with | When the environment changes |
| [`f_files.md`](f_files.md) | File-by-file map: what every file is and what it does | When a file is added, removed or repurposed |

Also here: `KAS-WS-0014-01-Events-Board-Workshop-Brief.pdf` — the printed
workshop brief. The living version of it is [`../TASKS.md`](../TASKS.md).

## The three project-root documents this folder does not replace

- [`../TASKS.md`](../TASKS.md) — the brief. What the product must do. The
  specification, not our notes about it.
- [`../CLAUDE.md`](../CLAUDE.md) — the house style Claude Code reads on every
  turn. Short on purpose. The memory bank explains; `CLAUDE.md` instructs.
- [`../AGENTS.md`](../AGENTS.md) — auto-generated by `next dev`, do not edit.

If a rule needs to be obeyed by Claude on every prompt, it belongs in
`CLAUDE.md`. If it needs to be *understood* by a human, it belongs here.
